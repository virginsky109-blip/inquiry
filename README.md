# Forwarding Quote System V2

`index.html` 하나로 실행하는 포워딩 견적서 출력기입니다.

## 실행

1. `index.html`을 Chrome 또는 Edge에서 엽니다.
2. **요율 관리**에서 담당자별 운임표와 안전운송운임표를 업로드합니다.
3. 운송 방식, Incoterms, POL/POD, 화물 정보를 선택합니다.
4. 자동으로 만들어진 부대비용을 확인·수정한 뒤 견적서를 저장하거나 PDF/Excel로 내보냅니다.

## AI로 운임표 읽기 (개인 PC용)

1. `AI_Setup.bat`을 실행하고 본인 OpenAI API 키를 한 번 입력합니다.
2. `AI_Helper_Start.bat`을 실행합니다. 실행 창은 견적 작업 중 열어 둡니다.
3. `index.html`의 **AI로 요율표 읽기**에서 Excel/CSV/JSON 파일을 선택합니다.
4. AI가 열 이름과 최대 30개 샘플 행만 보고 자료 종류와 열 연결을 제안합니다. 적용 전 결과 건수와 주의사항을 반드시 확인합니다.

키는 HTML, Git 저장소 또는 업로드한 견적서에 저장되지 않습니다. 현재 Windows 사용자만 읽을 수 있도록 암호화하여 `%LOCALAPPDATA%\ForwardingQuote`에 저장합니다. AI는 금액을 추측하지 않고, 파일에 있는 열을 표준 요율표 열에 연결하는 역할만 합니다.

## 요율 적용 우선순위 (Tariff Hierarchy)

운임(rate_master)은 3단계 우선순위로 조회됩니다. 항목별로 상위 단계에 없으면 다음 단계로 내려갑니다(Fallback).

1. **고객사 특약** — 화주명이 요율표의 고객사와 일치할 때 최우선 적용
2. **개인 표준** — 담당자 본인이 올린 표준 요율표
3. **전사 공통** — HTML에 내장된 기본 공통 운임. 새 브라우저·배포 환경에서도 자동 등록되어 견적 틀이 비지 않습니다. (`index.html`의 `SEED_COMMON_RATES`를 실제 요율로 교체해 사용하세요)

요율표를 업로드할 때(파일/AI 모두) 적용 범위를 지정하며, 요율 관리 화면에서 언제든 변경할 수 있습니다. 부대비용 표의 각 항목에는 어느 단계 요율이 적용됐는지(특약/표준/공통) 배지로 표시됩니다.

## 고객사별 견적 관리

- 화주명 입력창은 저장 견적·특약 요율표의 고객사명으로 자동완성됩니다.
- 고객사를 입력하면 해당 고객사의 특약 요율 적용 여부와 저장 견적(상용 항로)이 즉시 제안되며, 버튼 한 번으로 불러올 수 있습니다.
- 견적 저장 시 `고객사 항로 방식 V버전` 형식으로 버전이 자동 부여되고, 저장 목록에서 현재 고객사의 견적이 먼저 표시됩니다.

## 비고(Remarks) 표준 문구 체크리스트

디머리지·디텐션·오버스토리지·세관 검사비처럼 사전 예측이 불가능한 비용은 **계산에 넣지 않고 비고 문구로 방어**합니다. 유효기간·배차·지체료·세관검사·예기치 못한 비용·실비정산·부가세·실측 재정산·환율 기준·일반화물 기준 등 10개 표준 문구가 체크박스로 제공되며, 체크된 문구가 견적서 하단에 자동 삽입됩니다.

- 유효기간은 **실제 날짜로 입력**합니다. [월 반기(15일)까지] / [월말까지] 버튼으로 바로 지정할 수 있으며(기본값: 오늘이 15일 이전이면 당월 15일, 이후면 당월 말일), 문구에 해당 날짜가 자동 반영됩니다.
- **필수 문구(유효기간·실비정산·부가세)를 해제하거나 유효기간 날짜를 비운 채 인쇄/Excel 저장하면 경고**가 표시됩니다.

## VAT (부가세) 자동 계산

부대비용 표의 **VAT 열 체크박스**로 항목별 부가세 적용 여부를 관리합니다. 금액은 직접 입력하지 않고 `금액(KRW) × 10%`가 자동 합산됩니다.

- 기본 VAT 대상: 내륙운송료(TRUCK)·통관수수료·CFS 창고료·항공 창고료 등 영세율이 적용되지 않는 비용
- 기본 영세율(체크 해제): THC(터미널비용)·SEAL·항만보안료 등 보세구역 발생 비용, 국제운송료(OCEAN/AIR), 서류비(DOC/AWB — 국제운송용역의 필수 일부로 보아 영세율. 단순 국내 대행으로 과세 처리하는 경우 체크박스로 변경)
- 견적서에는 항목별 VAT 열과 함께 **SUB TOTAL(공급가액) / VAT / GRAND TOTAL(VAT 포함)**이 구분 표시됩니다.
- `charge_rule`에 `vat` 열(Y/N)을 추가하면 업로드 시 기본값을 지정할 수 있습니다.

## 계산 편의 기능

- **실시간 환율**: 적용 환율 옆 "실시간 불러오기"로 시장 중간환율(USD/KRW)을 즉시 반영합니다. 전신환매도율과의 차이는 수동 보정하세요.
- **MIN(최소금액)**: 항공 창고료처럼 `Max(계산액, 최소금액)` 산식이 필요한 항목은 부대비용 표의 MIN 열에 입력합니다. `rate_master`에 `min` 열을 추가하면 자동 반영됩니다. CFS 창고료는 RT(=max(CBM, TON)) 단위로 자동 계산됩니다.
- **A/B 옵션 비교**: 현재 견적을 [A안으로 고정]한 뒤 요율 세트·단가를 바꾸고 [A/B 비교]를 누르면 항목별 금액과 차액(B−A)을 나란히 확인할 수 있습니다. 프리미엄/이코노미 선사 제안 비교용입니다.

## 역할 분리 원칙 (하이브리드)

AI는 파일의 열을 표준 열에 **연결하는 역할만** 하고(구조화된 JSON 출력 강제, 로컬 브릿지 서버 경유), 금액 곱셈·합산은 전부 브라우저의 계산 코드가 수행합니다. AI가 금액을 추측하거나 계산하는 일은 없습니다.

## 지원 기능

- 단일 화면: FCL / LCL / AIR 및 EXW~DDP
- FCL: 컨테이너 타입(DRY/REEFER/OPEN TOP/FLAT RACK/DANGEROUS) → 사이즈(20FT/40FT/40HC/45FT) 2단 선택·대수 / LCL: CBM·TON·RT / AIR: G/W·CBM·C/W
- 요율표 `container` 열은 `40FT`(사이즈만), `REEFER 40FT`(타입+사이즈), `ALL` 표기를 지원하며, 타입+사이즈 일치 > 사이즈 일치 > 계열(40FT↔40HC) > ALL 순으로 우선 적용됩니다.
- 전사 공통 터미널 부대비용(THC 타입·사이즈별, 화물입출항료 항구별, 항만안전관리비·보안료·SEAL)은 HTML에 시드로 내장되어 있으며, 동일 데이터가 [공통_터미널부대비용_2026-07.csv](공통_터미널부대비용_2026-07.csv)로도 제공됩니다.
- 운송 조건에 따라 국내발생비용·해외발생비용·운임 항목 자동 구성
- 개인 브라우저별 요율 업로드 및 수정: CSV / JSON / Excel(.xlsx)
- 안전운송운임만 적용하는 내륙운송료 연동: 상·하차지 + 국내항 + 20/40 규격
- 사용자 직접 수정, 고객별 견적 저장/불러오기, 비고 입력
- 비용 규칙(Charge Rule) 업로드: 운송 방식·Incoterms·수출입별 표시 항목을 담당자가 변경
- PDF 인쇄 저장 및 Excel(.xlsx) 저장

## 운임표 양식

요율 관리 화면에서 양식 파일을 내려받을 수 있습니다.

`rate_master` 필수 열 (min은 선택 — 최소금액):

`chargeId, mode, pol, pod, container, amount, currency, min`

`safe_rate` 필수 열:

`place, port, size, amount`

`charge_rule` 필수 열:

`id, name, section, modes, terms, directions, unit, currency`

`modes`, `terms`, `directions`에 여러 조건을 넣을 때는 `|`로 구분합니다. 예: `FCL|LCL`, `FOB|CFR|CIF`, `export|import`.

안전운송운임에는 **안전운송운임(화주 청구 하한)** 금액만 넣습니다. 운수사업자간운임과 안전위탁운임은 넣지 않습니다. 기존 `안전운임_조회기.html`을 요율 관리 화면에서 그대로 업로드해도, 그중 안전운송운임 데이터만 자동으로 읽습니다.

## 데이터 보관 방식

업로드한 요율과 저장 견적은 기본적으로 해당 사용자의 브라우저(localStorage)에 저장됩니다. **클라우드 로그인**을 하면 팀 공용 DB(Supabase)와 동기화되어 모든 담당자가 같은 요율표·견적을 공유합니다. 로그인하지 않아도 브라우저 저장만으로 그대로 사용할 수 있습니다.

## 팀 공용 DB (Supabase) 설정 — 관리자 최초 1회

1. [supabase_schema.sql](supabase_schema.sql) 내용을 Supabase 대시보드 → **SQL Editor**에 붙여넣고 실행합니다. (테이블 + RLS 정책 생성)
2. **Authentication → Users → Add user**로 담당자별 이메일/비밀번호 계정을 만듭니다. (공개 가입은 사용하지 않음)
3. 각 담당자는 화면 상단 **[클라우드 로그인]** 버튼으로 로그인합니다. 로그인 시 클라우드 데이터를 자동으로 불러오고, 이후 요율표·견적 저장/삭제가 실시간 반영됩니다. 클라우드가 비어 있으면 로컬 데이터를 최초 1회 자동 업로드합니다.

동작 방식: 소규모 팀 상부상조 방침에 따라 로그인한 담당자는 전원 서로의 요율·견적을 조회/수정할 수 있습니다. 동시 수정 시 마지막 저장이 우선합니다(뼈대 단계 한계).

**보안 주의**: HTML에는 공개용으로 설계된 publishable key만 들어 있으며, 접근 제어는 RLS(로그인 필수)가 담당합니다. **secret key는 절대 코드·저장소·견적서에 넣지 마세요.**
